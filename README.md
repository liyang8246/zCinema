# Z Cinema

一个 **NeoForge 1.21.11** 的联机放映 Mod：不依赖机械动力（Create），
只支持 **MP4 直链**，让服务器里的小伙伴一起看视频。

灵感来自 [Create Cinema](https://github.com/Abuous/Createcinema)，
但播放模型被完全重写为「**客户端各自直连锁播 + 服务端只掌握时间轴**」。

---

## 屏幕长什么样

**没有新增可见方块**：用原版**黑色混凝土**贴一块平整的墙（任意大小），
然后**手持木棍 + 潜行 + 右键**其中任意一块 —— mod 会自动识别这块相连的平整混凝土区域，
把它合成一整块屏幕（自适应视频比例，黑边留白），**正面朝向你**。

被点中的那块混凝土会悄悄变成「屏幕核心」：外观、掉落物、Pick-block 都和黑色混凝土完全一样，
它只是用来记住这块屏幕的进度和链接。

| 操作 | 手势 |
| --- | --- |
| 创建屏幕 | 木棍/空手 + 潜行 + 右键 黑色混凝土 |
| 打开控制面板 | 右键 核心块（除木棍外的任意物品） |
| 撤下屏幕 | 木棍 + 右键 核心块，或面板里的「撤下屏幕」 |
| 播放/暂停/拖动进度 | 面板内操作，全员同步 |

## 它是怎么工作的

```
        ┌─────────────────────── 服务端（权威时间轴） ───────────────────────┐
        │  CinemaScreenBlockEntity: url / playing / waiting / position / anchor  │
        └───────────────┬───────────────────────────────────────────┬─────────┘
                        │ S2CState（全量快照，变更即发 + 每秒心跳）    │ ▲
                        ▼                                           │
        ┌───────────────┴──────────┐                     ┌───────────┴─────────┐
        │ 客户端 A（本地 FFmpeg）   │  ── C2S 控制事件 ──▶ │ 客户端 B（本地 FFmpeg）│
        │ 各自直链接流 + 解码 + 声音 │                     │ 各自直链接流 + 解码 + 声音 │
        └──────────────────────────┘                     └─────────────────────┘
```

- **服务端从不碰视频数据**，只维护一条时间轴：
  `实际进度 = positionMs + (播放中 && 未卡顿 ? now - anchorMs : 0)`
- 每个客户端用同样的公式按最近一次快照**外推**自己的本地时钟，
  各自用 FFmpeg 从同一个 URL 拉流、解码、播放（画面 + 声音都是本地的）。
- 事件（播放 / 暂停 / 拖动进度 / 卡顿上报 / 恢复）都是几十字节的小包，
  服务端改写时间轴后广播给所有能看到这块屏幕的玩家。

### 同步保证

| 事件 | 行为 |
| --- | --- |
| 暂停 / 播放 | 服务端冻结/继续时钟，全员跟随 |
| 拖动进度条 / 快进快退 | seek 即时间轴改写，偏差大的客户端会重开流定位 |
| 本客户端卡顿（缓冲耗尽） | 超过阈值后主动上报 STALL，服务端**冻结全员时钟**，等自己缓冲回来再 RESUME |
| 别的客户端卡顿 | 本地画面原地冻结，等它的 RESUME 到达后自动追平（必要时硬同步） |
| 正常播放 | 客户端轻微领先解码，快进/快退自动校正；偏差 > 2.5 秒（可配）自动重开流 |
| 新玩家加入 | 进 chunk 的瞬间就会收到当前快照，不会“从 0 开始” |

## 使用方法

1. 安装 [NeoForge 1.21.11](https://neoforged.net/)（21.11.x）。
2. 把 `zcinema-<版本>.jar` 丢进 `mods/`（服务端和客户端都装）。
3. 用**黑色混凝土**搭一块平整的墙（比如 9x5），**手持木棍 + 潜行 + 右键**墙上任意一块。
4. **右键**核心块 → 粘贴 MP4 直链 →「载入」→「播放」。

> 视频源必须是**直接的 mp4 链接**（支持 HTTP Range 的服务器体验最好；
> 不支持 Range 也能播，只是拖动进度会慢一点）。画面与声音各走一条 FFmpeg 连接，
> 声音打开失败会自动重试。

## 配置

文件位于 `config/zcinema-common.toml` 与 `config/zcinema-client.toml`：

| 配置 | 默认 | 说明 |
| --- | --- | --- |
| `syncIntervalTicks` | 20 | 全量状态广播间隔 |
| `globalStallPause` | true | 有人卡顿时是否冻结全员 |
| `bufferSeconds` | 1.5 | 本地解码领先共享时钟多少 |
| `hardResyncSeconds` | 2.5 | 偏差超过该值重开流 |
| `localStallMs` | 700 | 本地卡顿多久后上报 |
| `maxFrameWidth/Height` | 1920/1080 | 解码缩放上限 |
| `audioDistance` | 48 | 声音传播距离 |

## 构建

```bash
./gradlew build
```

产物在 `build/libs/`。默认捆绑 Windows/Linux/macOS 的 FFmpeg 原生库
（约 100MB+）；想要精简可以用
`./gradlew build -Pbundled_platforms=windows-x86_64`。

Java 21 与 Gradle 9.2+ 由 wrapper 自动处理。
